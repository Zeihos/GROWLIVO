## О проекте

**GROWLIVO** — игра, в которой путь к вершине начинается с одного клика. Зарабатывай очки, улучшай силу нажатий, собирай редких питомцев и открывай новые миры.

Проект находится в **стадии Alpha**. Здесь опубликованы актуальные исходники, установщик для Roblox Studio и фирменное оформление, а не готовая релизная сборка игры.

## Возможности

| Прогресс и награды | Миры и коллекция |
| :--- | :--- |
| 👆 Клики, улучшения ×1/×5/MAX и перерождения | 🌍 Три мира с разными множителями |
| ⚡ Комбо ручных кликов и автокликер | 🥚 Яйца ×1/×3/MAX, автооткрытие, каталог и слияние питомцев |
| 💎 Кристаллы, достижения и задания | 🔮 Испытания рун и временные усиления |
| 🏆 Таблицы лидеров и события | 🎁 Ежедневные сундуки с наградами |

Также реализованы адаптивный интерфейс, серверная проверка игровых действий и панель администратора. Каталог отображает **текущие виды питомцев в инвентаре**, а не историю когда-либо полученных.

### Открытие яиц MAX

В окне питомцев появилась кнопка **«🥚 MAX»**. Она открывает **до 10 яиц текущего мира одной операцией**. Количество зависит от баланса кликов, оставшихся мест (лимит 60 питомцев) и доступных ID. Цена за каждое яйцо обычная, без скидки.

Выбор питомцев, списание валюты и проверка лимитов выполняются на сервере. Все полученные питомцы учитываются для заданий и статистики. Для защиты производительности при массовом открытии показывается не более трёх эффектов выпадения. Схема DataStore и шансы выпадения не изменились.

### Массовое слияние питомцев

В инвентаре рядом с обычным слиянием есть **«×MAX»** для выбранного вида. После повторного подтверждения игра объединяет полные группы по **3 одинаковых снятых питомца**. Экипированные питомцы защищены, другие виды не затрагиваются, результаты не сливаются автоматически повторно.

**Начиная с Alpha 0.9.32, ×MAX сохраняет хотя бы один экземпляр исходного вида** (включая экипированных), чтобы массовое слияние случайно не отключало бонус коллекции. Например: из 9 снятых питомцев получится **2** результата и останется **3** исходных питомца. Если питомцев ровно 3 и ни один не экипирован, кнопка ×MAX будет заблокирована, но обычное слияние ×1 останется доступным. Если хотя бы одна копия экипирована, ×MAX может использовать все полные тройки снятых питомцев.

Расчёт групп выполняется на сервере, а клиент отображает тот же результат. Сервер проверяет инвентарь и лимит ID, затем сохраняет слияние как одно изменение профиля. В списке питомцев добавлена сортировка по редкости.

### Защита от случайных действий

**Перерождение требует двух нажатий за 5 секунд.** Перед сбросом кликов и уровня улучшений появляется предупреждение. При изменении стоимости, недоступности сохранения или истечении времени подтверждение сбрасывается; сервер повторно проверяет цену в момент покупки.

Кнопка индивидуального отпускания питомца восстанавливается после отклонённого сервером запроса, а повторное «Надеть лучших» с уже выбранными питомцами больше не создаёт лишнее изменение профиля и запись в очереди сохранения.

### Доступность покупки яиц

Кнопки **×1, ×3 и MAX** в окне питомцев автоматически становятся недоступными, когда не хватает кликов, свободных мест или ID. Доступность рассчитывается на клиенте по опубликованным сервером значениям для подсказки; сам сервер независимо проверяет покупку.

### Автоматическое открытие яиц

После **5 перерождений** в окне питомцев открывается кнопка **«🤖 АВТО»**. При включении сервер автоматически приобретает **одно яйцо текущего мира каждые 12 секунд**. Цена и шансы полностью совпадают с обычным открытием: бесплатных яиц нет.

Режим **автоматически отключается**, если не хватает кликов, свободных мест в инвентаре или ID питомцев. При недоступности сохранений и во время смерти персонажа автоматическое открытие приостанавливается. Во время задержек сервера пропущенные покупки не догоняются; изменения проходят через обычный серверный путь начислений, заданий и сохранения.

Автооткрытие не запускает полноэкранную анимацию каждые 12 секунд: вместо неё появляется короткое уведомление о питомце, не перекрывающее клики и движение. Ручное открытие сохраняет полную анимацию.

Включение действует **только на текущую игровую сессию**. Режим не записывается в DataStore; версия сохранений остаётся 7.

### Безопасная очистка дубликатов

В инвентаре доступна кнопка **«🧹 УБРАТЬ ДУБЛИКАТЫ»**: она предварительно показывает число освобождаемых мест и требует повторного подтверждения. Очистка удаляет лишние **снятые** экземпляры видов, сохраняя всех экипированных и минимум одного питомца каждого вида. Бонусы собранных коллекций не теряются.

Операция проводится сервером за один раз. Клиент не может указать список питомцев или количество удалений. Удаление необратимо; проверь список перед подтверждением. Слияние ×1/×MAX — отдельная операция. **Схема DataStore остаётся версии 7.**

### Бонусы за коллекции

Собери все виды питомцев одного мира **одновременно в инвентаре**, чтобы получить дополнительный процент к силе клика. Небесная корона даёт **+5%**, Кристальная долина — **+10%**, Роща сияния — **+20%**. Суммарно можно получить **+35%**. Это дополнительные процентные пункты к бонусу экипированных питомцев, а не самостоятельный множитель.

Прогресс каждой коллекции показывается в каталоге питомцев. Это не постоянное достижение: после потери последнего питомца нужного вида бонус соответствующего мира отключается до повторного получения вида.

## Установка

**Понадобится Roblox Studio.** Установщик добавляет игровые Script, LocalScript и ModuleScript в нужные сервисы проекта.

1. Открой Roblox Studio и **сохрани резервную копию** проекта.
2. Останови Play — установку нужно проводить в режиме **Edit**.
3. Открой [INSTALLER_CommandBar.lua](installer/INSTALLER_CommandBar.lua) и скопируй всё содержимое.
4. В Roblox Studio открой **Command Bar**, вставь код и выполни его.
5. Запусти Play и проверь окно **Output**.

> [!IMPORTANT]
> Перед обновлением обязательно делай резервную копию. Установщик сохраняет настроенные числовые AdminUserIds и предусматривает откат при ошибке установки, но не заменяет проверку игры.

### Как работают сохранения

- В неопубликованном Studio-place используется временное хранилище: после Stop прогресс сбрасывается.
- Для реальных проверок DataStore опубликуй **отдельную тестовую игру** и включи Studio Access to API Services в настройках безопасности.
- Не проверяй изменения сохранений на основных профилях игроков.
- Имя хранилища: `GROWLIVO_Profiles_v1`. Версия схемы: `7`.

~~~text
GROWLIVO/
~~~

| Раздел | Содержимое |
| :--- | :--- |
| [**src/**](src/) | Вся игровая логика: экономика, миры, питомцы, интерфейсы, сохранения |
| [**installer/**](installer/) | Готовый установщик через Command Bar |
| [**assets/**](assets/) | Фирменные материалы GROWLIVO |
| [**tools/**](tools/) | Проверка соответствия исходников и встроенных копий |
| [**GitHub Actions**](.github/workflows/verify-installer.yml) | Автоматическая проверка при изменениях |

### Для разработчиков

Основной код находится в `src/`. В установщик встроены копии всех 24 скриптов. После изменения исходников обнови установщик автоматической командой:

~~~bash
python3 tools/sync_installer.py --write
python3 tools/check_installer.py
python3 tools/check_gameplay_contract.py
~~~

Команда без `--write` ничего не меняет: `python3 tools/sync_installer.py --check` проверяет совпадение копий. При добавлении нового скрипта сначала укажи его имя, класс и место установки в списке `packages` внутри установщика.

Дополнительно: [как предложить изменения](CONTRIBUTING.md) и [как сообщить об уязвимости](SECURITY.md).

Проверка GitHub Actions подтверждает соответствие файлов и проверяет таблицы выпадения/контракты автооткрытия. Это **статические проверки**, а не замена тестированию внутри Roblox Studio.
